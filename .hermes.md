# neanbit type — reglas del proyecto

Práctica de mecanografía en español (type.neanbit.com). Front estático y
servidor Node sin dependencias. README.md es la documentación canónica: si
cambia una regla o la estructura, actualizalo en el mismo cambio.

## Reglas duras
- Solo navegador. Nunca proponer Electron ni una app de escritorio.
- Nada de Firebase ni Supabase: ni dependencia, ni servicio, ni ejemplo.
- Front estático con módulos ES y sin build. No agregar bundlers,
  transpiladores ni paso de compilación.
- Servidor Node >= 22.13 sin dependencias externas: solo `http`,
  `node:sqlite` y el WebSocket propio. No sumar paquetes a package.json
  sin pedirlo antes.
- SQLite en modo WAL.
- Código y estética propios, sin emojis. Los íconos son SVG de línea propios.
- Paleta fija: fondo `#14213d`, texto `#f1f5f9`, acento `#fca311`.
  Tipografías Poppins e IBM Plex Mono.

## Mapa
- index.html, css/, js/   front, módulos ES, sin build
- server/                 http, sqlite, ws, duelos, torneos, niveles,
                          medallas, recompensas, xp
- deploy/                 units systemd, esquema.sql, backup, cloudflared
- scripts/                audit-seguridad.sh, backup.sh, export-content.mjs
- img/                    marca y logos

## Repo hermano: neanbit-type-admin
Ruta: `~/projects/neanbit-type-admin` (el panel de administración, privado). Leerlo siempre se puede; editarlo solo cuando el pedido diga que hay que hacer cambios en ambos repos.
- Archivos de `server/` que son copias exactas en los dos repos (si cambiás uno, hay que cambiarlo igual en el otro): `content.js`, `html-safe.js`, `levels.js`, `medals.js`, `rewards.js`, `track.js`, `xp.js`, `content-defaults.json`.
- `server/index.js` es propio de cada repo: no es una copia.
- `server/limits.js` existe solo en esta app; `server/rewards-presets.js` existe solo en el panel.
- Si tocás un archivo compartido, avisame al final y comprobá la sincronía con:
  `cd ~/projects && for b in content.js html-safe.js levels.js medals.js rewards.js track.js xp.js content-defaults.json; do cmp -s neanbit-type-admin/server/$b neanbit-type/server/$b && echo "IGUAL $b" || echo "DISTINTO $b"; done`
- Cambio en ambos repos = dos ramas con el mismo nombre `mind/<tema>`, un commit y un push en cada una, dos diffs para que yo revise. Nunca merge. Cada `git` se corre parado dentro de su repo (cada uno usa su propia llave SSH).
- El panel nunca se expone a internet y se prueba solo con bases temporales en `/tmp`: esas reglas están en su propio `.hermes.md`.

## Flujo de Git
- Antes de empezar una tarea: git switch main, git pull y crear una rama nueva con prefijo mind/ (por ejemplo mind/arreglo-x). Nunca trabajar directo en main.
- Nunca hacer push a main, merge, git reset --hard, push forzado ni borrar ramas sin que se te pida expresamente.
- Un commit por tarea, con mensaje claro en español (docs:, fix:, feat:).
- Antes de terminar, mostrar git diff main --stat y listar los archivos cambiados.
- Si algo no sale como se esperaba (conflictos, errores), frená y avisame; no intentes arreglarlo por tu cuenta.

## Verificación
- No hay script de test ni de lint en package.json. Antes de dar algo por
  terminado: `node --check` sobre los archivos tocados y un arranque limpio
  con `NT_DB=/tmp/prueba.db PORT=3000 node server/index.js`.
- Auditoría de seguridad: `bash scripts/audit-seguridad.sh`.
